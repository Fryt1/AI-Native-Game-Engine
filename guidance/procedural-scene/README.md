# 程序化场景生成

从零生成一个可交付的场景资产：一套几何、一个材质与贴图集、一个灯光相机，
以及一组可复查的验收证据。

本文件是这份 guidance 的**入口文档**。它描述生命周期和不变量；具体怎么调用由
Agent 按 `templates/workflow.schema.json` 生成 Workflow 时决定。

---

## 适用范围

适用于**生成**场景，不适用于编辑既有资产、在宿主间搬运资产、或应用外部产物。

---

## 生命周期

```text
探活宿主  →  生成  →  网格完整性  →  环境  →  渲染
```

每个阶段都是必需的，顺序不是任意选的：

- **探活在前**，因为后面每个阶段都依赖一条活着的桥；
- **完整性先于环境**，因为灯光和渲染是最贵的一步，结构坏掉的网格不该走到那里；
- **环境先于渲染**，因为相机必须先存在。

---

## 不变量

1. **调用返回成功，本身不构成阶段完成。** 阶段只在冻结的验收项通过时完成。
2. **计数一律从宿主读回**，绝不采信生成器的自报。
3. **有界扫描必须报告覆盖率**；部分覆盖绝不能被当作完整覆盖。
4. **本文档不预填任何验收阈值。** 每个数值都由执行者实测填入 —— 见
   `docs/why-no-thresholds.md`。

---

## 每个阶段的义务

| 阶段 | 本地目标 | 必须证明 |
|---|---|---|
| 探活 | 确认桥可达、版本匹配、引擎枚举 | 读取返回真实宿主数据；引擎集来自宿主而非硬编码 |
| 生成 | 在宿主中建场景并独立读回 | 面数、对象数、材质数达标；计数来自读回 |
| 网格完整性 | 证明几何结构健全 | 无退化面、无沉地、组齐全、共面在预算内 |
| 环境 | 建世界、灯光、相机并落盘 | 相机存在；文件非空 |
| 渲染 | 出图并证明是真实画面 | 每张图存在且非空白；分辨率达标 |

---

## 完成

所有阶段的冻结验收项通过，且 `finish` 返回 `succeeded`。

**阶段 `pass` 只证明 Agent 做到了自己清单上的事**，不证明场景好看。
无法确定性度量的质量属于 `needs_human`，不属于一个新造出来的阈值。

---

## 失败与恢复

| 失败 | 应对 |
|---|---|
| 桥不可达 | 重试探活；**不要**继续生成 |
| 某次调用失败 | 重试该调用，然后重规划该阶段 |
| 必需检查返回 `unknown` | 继续取证；取不到就如实报告缺什么 |
| 检查需要人判断 | 记为 `needs_human` 并等待 |
| 序列本身错了 | 用 `supersede` 写一个替代修订 |

详见 `docs/recovery.md`。
